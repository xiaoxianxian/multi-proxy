# EVAL · 每成功任务成本验收协议

> 版本：v1（2026-10-18）｜适用：任何"路由/降本"类改动的前后对照，以及 M6 的 D0 真实样本
> 配套脚本：`scripts/cost-per-success.js`（离线复算，自带自测）
> 立此协议的直接原因：看一眼 2026-10-18 那篇厂商实测稿，它的通过率对照在统计上是噪声，却写成了结论。

---

## 一、为什么要有这份

现在的账本能回答"每 token 多少钱"，回答不了"办成一件事花多少钱"。四处缺口，都是实核：

| 缺口 | 证据 |
|---|---|
| 省钱测算是模拟值，不是账单 | `scripts/savings-case.js:82-83` 自己印着"⚠️ 定价表模拟值，非真实账单" |
| 真实样本一直没攒够 | `docs/M6-REAL-ROUTING-SIGNOFF.md:43` 与 `:82` 要求 `routing_feedback` ≥100 行；2026-10-18 只读查询 = **0 行** |
| 成本账本没有稳定真实流量 | `~/.multi-proxy-manager/cost-ledger.jsonl` 共 **42 行**，首几行 `model:"<unknown>"`、`cost` 为固定值 |
| override 只跑过手工验证 | `cursor-proxy/data/override-audit.jsonl` 共 **2 行**（2026-10-06） |

结论：**能答单价，不能答成事成本。** 本协议补的就是这一格。

---

## 二、三条硬规矩（不可协商）

### 规矩一：证据链自己写，不接受被测方提供

任务集自己出，验收脚本自己写。哪怕写得糙，也必须是自己写的。

> 反面样本：2026-10-18 那篇实测稿，正文自述"测试环境、任务集与验收脚本**由被测方提供**"。裁判是被告自己写的，跑得再认真，也不叫独立评测。

### 规矩二：先写清"什么叫完成"，再开跑

每一题在跑之前就要有**可判定**的完成条件，写进题目文件。不许事后按结果放宽。

可判定 = 机器能判或人能一眼判："金额算对且排序一致"、"改了 3 个文件且 `npm test` 全绿"。
不可判定 = "代码质量不错"、"回答比较全面"。**不可判定的题不许进任务集。**

### 规矩三：失败不剔除，钱照算

- 完成率的分母 = 全部运行次数，不是"有效运行次数"。
- 平均等待的分母同上，失败的超时也要计入（它们真的让你等了）。
- 花费的分母 = 全部运行，包括失败那几次的钱。

> 唯一允许剔的：题目本身有错、重跑前修正过的那几次。剔了必须在报告里写明剔了几条、为什么。
>
> **2026-10-18 新增第二类可剔项：账号/额度/网络中断。** 当天实测就撞上了：跑到第 18 次，上游开始回 `HTTP 402`，后面 31 次全是欠费，不是模型答不出来。这种行必须标 `invalid:true`，从完成率里剔除，并在报告里写明剔了几条。**理由：欠费是环境故障，把它记成模型失败，等于用"我没钱"证明"这个模型不行"。**

## 三、任务集：12 题怎么出

三类各 4 题，**全部取自你自己每天真干的活**，不许用跑分题。

| 类 | 题型 | 验收条件示例 |
|---|---|---|
| 编码修复 | 给它一个能复现的失败用例，让它改到测试全绿 | 指定测试命令退出码 0，且未改动测试文件 |
| 长文改写 | 给一篇 3000 字旧稿，让它按给定规范改到合规 | 脚本机检 0 命中，且字数变化在 ±10% 内 |
| 表格核对 | 给两张有差异的表，让它找全差异 | 差异集合完全一致（多报少报都算失败） |

- 每题**跑 2 次**（24 次/组），同一题两次之间清空上下文，避免缓存让第二次变简单。
- 组数至少两组：**一个固定最强模型作基线，一个被测方案**。
- 想比较两个路由方案，就再加一组，别拿"基线"和"方案"混着比。

## 四、记录格式

一行一次运行，UTF-8 JSONL，追加写：

```json
{"task_id":"t01","group":"multi-proxy","passed":true,"duration_s":139.7,
 "cost_cny":0.0372,"judge_cost_cny":0.001,"steps":3}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `task_id` / `group` | ✅ | 题目 ID / 组名 |
| `passed` | ✅ | 布尔值，只认完整通过 |
| `duration_s` | ✅ | 请求发出到结束，含重试与工具调用 |
| `cost_cny` | ✅ | 实际计费，不用单价乘估算 |
| `judge_cost_cny` | 选填 | **判定层自己的花费单列**，缺省 0 |
| `steps` | 选填 | 本次运行发生了几个 step 级请求 |

`judge_cost_cny` 单列这条是硬要求：判定开销混进总账里，就再也算不出"为了省钱先花了多少"。

## 五、四个指标

| 指标 | 公式 | 为什么是它 |
|---|---|---|
| 完成率 | 通过数 ÷ 运行数 | 分母不许缩 |
| 平均等待 | 全部 duration 之和 ÷ 运行数 | 失败的不剔除 |
| **每成功任务成本** | **总花费 ÷ 通过数** | 主指标。分母是硬约束，干不完的活不计入成功，钱却照付 |
| 判定开销占比 | 判定花费之和 ÷ 总花费 | 回答"为了省钱先花了多少" |

⚠️ **主指标不是"省了百分之几"**。省钱比例的分母可以随便挑，通常挑最贵那一档，于是数字好看；每成功任务成本的分母挑不了。

## 六、判读门槛（这一节最容易被跳过）

**24 次/组，只够看出"差一大截"。** 用 Fisher 精确检验实算（`scripts/cost-per-success.js` 内置）：

| 每组次数 | 现实档位下，差几次才开始显著（p<0.05） |
|---|---|
| 24 | 20/24 vs 12/24，差 **8 次**，p=0.030 |
| 30 | 24/30 vs 15/30，差 9 次，p=0.029 |
| 50 | 36/50 vs 25/50，差 11 次，p=0.040 |
| 100 | 65/100 vs 50/100，差 15 次，p=0.045 |

**读法**：
- n=24 时差 3 次（83.3% vs 70.8%）→ **p≈0.49，是噪声**。这种量级不许写成"通过率更高"。
- 想证明"5 个百分点的提升"，24 次远远不够，得几百次。
- **p≥0.05 时只能写"未见显著差异"**，不许写"略高""更好""有优势"。

## 七、反作弊清单（每条都对应一个真实事故）

| # | 坑 | 怎么防 |
|---|---|---|
| 1 | 只跟最贵的基线比 | 同时报"每成功任务成本"，并列出与最便宜组的对比 |
| 2 | 只在"双方都通过"的子集上比成本 | 子集比可以，但必须同时报全量口径，两个数并排放 |
| 3 | 不同指标的分母混用 | 每个成本数字都标注分母（几次运行 / 几对 / 每百万 token） |
| 4 | 判定费藏在总账里 | `judge_cost_cny` 单列，算出占比 |
| 5 | 把噪声写成结论 | 每组报 p 值，p≥0.05 只写"未见显著差异" |
| 6 | 用被测方提供的验收脚本 | 规矩一，自己写 |
| 7 | 验收条件只写负面约束（不许出现什么），不写产出量 | 2026-10-18 实测：弱模型把"改写"做成"概括"，破折号没有、套话没有、关键词也在，只是字数只剩原文 32%-83%。去掉字数约束，同一批运行的通过率从 **0/8 变 6/8**，结论直接翻面 |
| 8 | 把不同难度的任务塞进同一个标签 | 2026-10-18 真稿复测：**同一个模型、同一个验收脚本**，只换一批原文，改写类结论从 `0/8（不可降档）` 变成 `6/6（可降档，省 92% token）`。原因是首轮原文是 AI 腔待修稿——删掉套话必然掉字数，要保字数就得补实质，那已经是重写不是改写。见 `eval/2026-10-18/real/REPORT-真稿改写-2026-10-18.md` |

第 7、8 两条是同一件事的两层：**题目怎么出，比模型怎么答更能决定结论。** 所以听到"某某模型在某类任务上不行"，第一个该问的不是"评测跑了几次"，而是"**你说的这类任务，具体是哪些题**"。

## 八、怎么跑

```bash
# 0) 生成任务集（题目正文、初始 bug、验收命令由同一脚本产出，避免三处对不上）
python3 eval/2026-10-18/build.py

# 1) 自测（不联网，验证统计内核）
node scripts/cost-per-success.js --selftest

# 2) 跑一轮（串行；每次调用带随机 nonce 强制不吃缓存）
python3 eval/2026-10-18/runner.py --out eval/2026-10-18/runs-YYYY-MM-DD.jsonl \
    --group strong=deepseek-v4-pro --group cheap=deepseek-v4-flash

# 3) 逐题/分类/路由决策三张表
python3 eval/2026-10-18/analyze.py eval/2026-10-18/runs-YYYY-MM-DD.jsonl

# 4) 复算主指标（默认拿第一组当基准，或用 --baseline 指定）
node scripts/cost-per-success.js eval/2026-10-18/runs-YYYY-MM-DD.jsonl --baseline=strong
```

输出的四列就是第五节那四个指标，末段直接给"与基准组的差异 + p 值 + 判读结论"。

### 8.1 计费口径：0 和"不知道"必须分开

网关侧其实早有计费（`cursor-proxy/src/routing/actualCost.ts` + `monitoring/costTrack.ts`，门控 `PROXY_CURSOR_COST`），但它只往 sidecar `~/.multi-proxy-manager/cursor-cost.jsonl` 写，**不回传给调用方**。所以 runner 侧拿不到金额，只能自己从 usage 折。

自己折的前提是价能回源。折完的账必须连 `cost_basis` 一起看，因为 **`cost_cny: 0` 有两种完全不同的意思——"免费"和"不知道"**。分不清这两个，就会有人拿 0 当分母，算出"省了 100%"。

四种口径（`eval/2026-10-18/pricing.py`）：

| basis | 含义 | 能不能拿来算钱 |
|---|---|---|
| `pricing-table@{updatedAt}` | 有官方公开单价，按它折（价格带 source 与更新日期） | ✅ 能 |
| `unbillable:subscription` | 订阅制/额度包，**单次调用花多少钱在定义上就答不出** | ❌ 不能 |
| `zero:local` | 本地模型，真 0 元（但有硬件摊销，不可与云价直接比） | ❌ 不能 |
| `unknown-model` | 价表里没有这个模型，**不猜** | ❌ 不能 |

⚠️ **最关键的一条：订阅制那档比"不填"更危险的是"填 0"。** 本机价表里 `agnes-3.0-flash` 的 `source` 标的是 `official-agnes`、值却是 `0/0/0`——这两个信号互相打架：标了官方来源说明有人填过，给零值说明填不出来。我核过 apihub.agnes 的公开定价页，**没核到按量单价**，所以按 unbillable 处理，不当免费。

统计口径的硬校验（`scripts/cost-per-success.js`）：**只要一组里掺一行不可折的记录，整组的金额列置空，省钱比例输出"不可比"**。宁可全废，也不让半真半假的数进报告。

想比钱而拿不到单价时：先补 `pricing.py` 的 `PRICING`；想现在就比，用 `--unit=tokens` 看 token 账——它不等同钱，但至少分母是实的，且**必须写明是 token 口径**。

> 价表从 `cursor-proxy/src/pricing/seed.ts` 的 `OFFICIAL_PRICING` 抄录（两套运行时，改价请先改 seed.ts 再同步 pricing.py）。折账公式与 `actualCost.ts:16` 对齐：`(in − cache) × input + out × output + cache × cacheHit`。⚠️ `in_tok` 通常**已包含** cache 部分，必须先减再算，否则缓存部分被按原价重算一遍，账虚高。

## 九、跟 M6 的关系

本协议是 `docs/M6-REAL-ROUTING-SIGNOFF.md:43` 那个 D0 缺口的补法之一，但**不替代**它：

- D0 要的是 `routing_feedback` ≥100 行**真实流量**（用户实际请求，不是造题）；
- 本协议要的是 **12 题 × 2 次**的可控对照（能归因到某个改动）。

两者一个管"线上有没有 mis-route"，一个管"改动到底有没有用"。**先跑本协议拿到可归因的对照，再开 override 灰度攒真实流量**，顺序别反。

## 十、边界（写清楚，免得下次当结论用）

1. 本协议的样本量**只够发现大差异**。12 题 24 次的结论是"没有明显变差/变好"，不是"等价"。
2. `cost_cny` 必须是实际计费。拿单价乘估算填进去，等于把 `savings-case.js` 那个模拟值换个名字再用一遍。
3. 12 题**不能代表你的全部负载**。改完负载结构（比如新增一类任务），任务集要跟着改，旧结论作废。
4. p 值只处理随机波动，**不处理系统性偏差**（题目泄漏、缓存让第二次变简单、验收脚本写松了）。这三项得靠第三节的流程约束。
