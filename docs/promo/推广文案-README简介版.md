# multi-proxy + Portico —— 把 AI 出网收口到你自己机器上

> 一句话：大厂在做“云端 AI 网关”，我们在做“本地优先”那一层。同一痛点（模型混乱 / Key 散落 / 账不清 / 没兜底），两条路径，不互斥。

## 我们解决什么

- **multi-proxy**：把 Codex / Cursor / Claude Desktop / OpenCode 等编码代理统一收口到本地一个端点。统一入口路由、本地 .env 收口各家密钥、端口冲突检测（OCCUPANT_PORTS）、本地 Ollama 一等公民、可视化切换面板、L2 熔断。
- **Portico**：坐在旁边、不进流量链的本地控制面，只管审计和出网——确定性审计回放（把判据原样重放）、出网管控。当前单用户 / 单机版本；多租户 / SSO / 企业分账在规划路线上，未动工。

## 和火山 AgentKit / 阿里云 AI 网关不互斥

它们是**云端组织治理层**（密钥托管、计量分账、合规）；我们是**本地优先层**（账本主权握在你自己手里）。两层相邻，按需叠加：本地编码代理 → multi-proxy（本地路由）→ 云网关（组织治理）→ 模型厂商；Portico 在旁边管审计和出网。

叠着跑的时候你手上会有两本账，云网关一本、本地一本。本地那本是你对账的底稿。

## 你得到什么

- 账本主权：计量、分账、审计这三类记录记在你机器上，谁能改由你定
- 本地模型（Ollama）一等公民，不强制上云
- 端口 / 配置冲突可被只读仲裁者卡住，防静默夺线
- 确定性审计回放：出了问题自己复现，不用先信厂商的日志
- 代码公开可审、可分叉，跨 provider 不被锁

关于数据不出域：厂商有专有云和私有化形态（火山 AgentKit 可部署在企业私有 VPC 内，阿里云 AI 网关有飞天专属版），合规场景他们接得住。差别不在数据放在哪个机房，在账本 custody 归谁。

## 本地这一层的真实代价

一台机器的看护、升级、故障单点；叠着云网关跑还有双跳延迟和两本账的对账成本。算完这些还选本地，才是真需求。

顺带一句，本地这一层不止我们：LiteLLM 这类开源通用网关做的就是多模型代理加虚拟密钥加计量，自托管，协议覆盖比我们全。我们多做的是那几道本地闸门：端口冲突、本地模型、判据回放。
