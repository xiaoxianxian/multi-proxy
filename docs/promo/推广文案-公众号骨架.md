## 标题（已定）

**大厂把 AI 网关做成生意，但账本主权那层他们给不了**

> 原标题候选 1 是“他们不给你”。“不给你”是动机指控，“给不了”是能力判断，与正文共存姿态自洽（贵人视角 P1-4）。

## spine / 核心立论

大厂抬高了“AI 网关”这个品类的声量，但这门生意里有一块只有跑在你机器上才成立，就是账本主权那一层。云网关握合规分账（组织层），本地优先握账本主权（本地层），两层相邻，不互斥。

> 立论口径已按专有云核结果收窄：数据不出域厂商有专有云 / 私有化形态，不能再当作本地独占护城河（2026-10-15 核）。

## 章节骨架（每节回答一个具体问题）

1. **引子**：火山 / 阿里都把 AI 网关摆上台面，先给判断（品类声量被抬高，但有一块只在本地成立）。触发素材降级为证据位，不写“我刷到说”。
2. **定义**：账本 = 计量、分账、审计三类记录；账本主权 = 这份记录记在哪儿、谁能改。（核心 coinage 必须钉死，读者视角 5/10 的主要扣分点）
3. **一、大厂在解决同一组老痛点**：四个坑（模型混乱 / Key 散落 / 账不清 / 没兜底）+ 云端解法。数字标“官方口径·非实测”；“响应快 300%”已删（厂商未说明基数）。
4. **二、但云端的解法有它够不到的地方**：它们不在你机器上跑。multi-proxy 接住前两个坑（统一入口路由 + 本地 .env 收口密钥）；只有跑在你机器上才成立的：端口冲突检测、本地 Ollama。Portico 在旁边不进流量链，做确定性审计回放（自证 vs 他证）。
5. **三、两条路径不互斥**：叠着部署的两本账——云一本、本地一本，本地那本是对账底稿。Portico 不在链上。
6. **四、逐项看**：插【能力对比矩阵】图。★ 三项（端口冲突检测 / 本地 Ollama / 确定性审计回放）；MCP 管理与数据不出域标半格，不嘴硬。
7. **五、Portico 视角：控制权归谁**：custody 归谁（不用“数据出境”——境内场景不成立，可证伪）。本地真实代价先摆：运维、单点、双跳。竞品段：LiteLLM 这类通用网关已在这一层。
8. **六、选型看层，不看出身**：什么人选云、什么人选本地；本地是手段不是结论；给可搜项目名做转化位。插【生态定位图】。
