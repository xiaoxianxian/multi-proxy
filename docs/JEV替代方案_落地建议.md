# JEV 替代方案 · multi-proxy 落地建议

> 配套文档：《Jev替代方案_详细分析与执行计划.md》（主文档，含 Phase 1.5 复现命令）+ 《Jev开源替代方案_横向对比.md》（含 §2.5 本机实跑基准）。
> 本文件只给 multi-proxy 可直接照做的结论与集成点。更新：2026-09-24 本机实跑后定稿。

## 0. 一句话结论

**multi-proxy 的路由用「Qwen3Guard 安全闸门（先）+ Laya 良性路由（后）」双保险。** 单用 Laya 做路由 = 把越权/绕过审核/泄露隐私的请求直接放给下游模型（**本机实测 Laya 路由"安全敏感"意图 0/4 全漏判**），必须先用 Qwen3Guard 截一道。

## 1. 架构（双保险，顺序不可反）

```
请求进 18791 面板前
   │
   ├─[Qwen3Guard-0.6B 安全闸门, 本地MPS ~500ms]── 命中 Unsafe → 拦截/告警，绝不放行到下游模型
   │     （Laya 看不见安全，不能单独兜底安全，见 §2）
   │
   └─[Laya-multi 良性路由, ~40ms]── 判"简单/复杂""代码/问答/写作/生图"等 *非安全* 意图
         简单/良性 → 小模型 / 本地 qwen3.8
         复杂     → 大模型 / 高 reasoning
         低置信   → 转层 A（qwen3.8 结构化）兜底
```

## 2. 为什么 Laya 不能单独做路由（铁证）

本机实跑 Laya 路由（7 类意图，各 4 条，28 条中文样本）：

| 意图 | 命中 | 备注 |
|---|---|---|
| 简单问答 | 4/4 | 稳 |
| 代码 | 4/4（但吞掉别类 4 条） | **代码偏置**：求职信/短视频分镜/系统架构拆解误判为"代码" |
| 写作创作 | 3/4 | |
| 图片视频生成 | 2/4 | |
| 复杂推理 | 3/4 | |
| **安全敏感** | **0/4** | ⚠️ 全部漏判（"绕过内容审核""泄露他人隐私"→判成"简单问答/复杂推理"） |
| 闲聊 | 2/4 | |
| **合计** | 18/28 = 0.64 | 延迟 ~69ms；平均置信 0.73 |

**结论**：Laya 只适合高频**良性意图分流**（快、便宜、零调用费、误路由代价低）；**安全判定必须独立交给 Qwen3Guard**。

## 3. 部署与复现

- Qwen3Guard-0.6B 权重已下到 `/Users/xiaota/WorkBuddy/2026-09-18-14-08-21/.bench/models/Qwen3Guard-Gen-0.6B`。
- Laya：`pip install laya`（已装到隔离 venv `/Users/xiaota/.workbuddy/binaries/python/envs/default`），首次 `Router().preload(["multilingual"])` 自动从镜像拉权重。
- 完整可复现脚本：`.bench/bench.py`（含两套模型的审核/路由评测）。
- ⚠️ 跑本地 ML 前必须 `export PYTHONPATH=`（见主文档 Phase 1.5），否则被 WorkBuddy 文件代理拦截。
- 生产建议：Qwen3Guard 做异步安全闸门（~500ms 别串行拖热路径）；Laya 同步做良性路由。

## 4. 风险与回滚

| 风险 | 应对 |
|---|---|
| Laya 路由漏安全（0/4） | Qwen3Guard 先于 Laya 截安全；Laya 只管良性意图 |
| Laya 代码偏置 / 中文路由 0.64 | 接受零样本不完美；或用 **Kev**（可本地自训专属路由器）补细分；LLM 兜底 |
| Qwen3Guard ~500ms | 异步/并行，不阻塞热路径 |
| 误路由代价低（顶多变慢/变贵） | 阈值按实测调，必要时转 qwen3.8 兜底 |
