## 0 · 全局可读性总则（老板⑤ + ② + ③，3 个表面统一遵守）

这一节是 3 个表面的共同约束，先定死，下面每个表面只写差异。

| # | 总则 | 落到交互 | 反例（绝不做） |
|---|------|---------|----------|
| K1 | **可读铁律**：人话 + 告诉下一步 | 每条告警三件套：①发生了啥 ②对路由/钱的影响 ③你能咋办 | 甩 `ERR_PRICE_DRIFT` / `drift_pct=12.5` / 原始 JSON 给用户 |
| K2 | **哨兵非执行器** | 任何"价格/路由/配额变化"默认 observe；用户不点，系统不动 | 自动改价 / 自动切路由 / 自动超额执行 |
| K3 | **原币永不丢** | 换算值旁必带原币；换算值放次要色、原币放主色 | 只显 `¥18.0/M` 让用户忘了充值是 USD |
| K4 | **绝不假死** | 预检失败/配额拿不到 → 不阻塞，带 warning 继续；执行中 80% 先存进展再优雅停 | 卡住不动 / 静默跑空 / 任务中途丢失 |
| K5 | **门控默认关** | 3 个表面各自有 observe 默认态；翻成"自动执行"属老板单点决策 | 默认就让 toast 自动替用户点"替换" |

**通知通道（复用，不新建）：**
- 后端哨兵 → `l2/alert.js` 内核（`emit` / `observeOnly` / `DEFAULT_CONFIG.cooldownMs` 去重）。价格漂移走 `PROXY_PRICE_DRIFT_NOTIFY`(observe 默认关) + 24h 去重；配额走 `PROXY_QUOTA_GUARD`(observe 默认关)。
- 前端触面 → `showToast(msg, level, ms)`（4 级：success/error/info/warning）+ 持久型 `banner`（参照 `.offline-banner` 做法）+ 跨页 `BroadcastChannel('proxy-status')` 广播刷新。
- **已知可访问性债（继承自 `09-review/8-UI设计师.md`，本稿强制补）：** 现有 `.toast` 无 `role="status"`/`aria-live`；现有 modal 无 `role="dialog"`/Esc/焦点陷阱。本稿 3 个表面**必须**补齐：toast 加 `role="status" aria-live="polite"`；三选一弹窗加 `role="dialog" aria-modal="true"` + Esc 关闭 + 焦点陷阱 + 关闭后焦点归还原触发钮。

**数值排版（统一）：** 数字一律 `--font-mono`（JetBrains Mono）。原币主色 `--color-text`；换算 CNY 用 `--color-text-secondary` 并以 `≈` 衔接；告警值用 `--color-warning-deep`/`--color-error-deep`（AA 对比，参照 visual-design §2.1 `*-deep`）。

## 1 · 表面 A · 价格漂移 Toast / 条幅（§3.10 + §3.2）

### 1.1 设计意图
渠道会漂、OpenRouter 会波动。系统当**哨兵**：发现某模型官方价变动、且**可能改变路由排序**时，弹明显条幅/toast，让用户自己决定"替换"还是"忽略并设静默期"。**绝不自动用新价覆盖当前在用的价**（§3.2 信任边界铁律：用户价格主权 > 一切）。

### 1.2 触发时机与门控
| 项 | 取值 | 说明 |
|----|------|------|
| 触发源 | `refresh-pricing.cjs` 刷新后（手动 / 可选 auto / 定时），产 `pricing-cache.json`（L2），与现生效价比 | 刷新只产数据、不动路由（热路径零网络，非侵入铁律） |
| 触发条件 | 偏差 > `PROXY_PRICE_DRIFT_PCT`（默认 **10%**） | 低于阈值 → 静默，不骚扰 |
| 排序关联 | 载荷带 `orderChanged`（旧排序 vs 新排序 diff） | 关键：一眼看出"是否让某模型跳了名"，如 Kimi 第 3→第 1 |
| 去重 | 同 `model` 同偏差方向 **24h** 内只告一次（`PROXY_PRICE_DRIFT_SUPPRESS[name]=<hours>`，默认 24h） | 防 OpenRouter 波动刷屏；与 alert.js `cooldownMs` 同机制 |
| 用户价保护 | `_userSet:true`（L1 用户覆盖）的价**永不被建议覆盖**，即使官价变 | 这条不弹"替换"，只可"忽略" |
| 门控 · 后端 | `PROXY_PRICE_DRIFT_NOTIFY`（observe，默认**关**） | 关 = 内核收集漂移事件但不外发；开 = 产出可被前端消费的漂移事件 |
| 门控 · 前端 | toast 为**只读镜像**：它只显示内核已采到的漂移事件，**本身绝不改价/改路由** | 故"toast 是否可见"与"是否自动改价"解耦（见 §1.6 老板可调项 D-A1） |

### 1.3 文案示例（精确到用户看到的字，中文，可读）

**形态：持久型条幅 banner（非一闪即逝 toast），因为要用户读+决策。** 顶部常驻，未处理不自动消失；处理完转 success 后 3s 淡出。

**文案 · 主态（有排序变化时，高优先）：**
```
⚠️  DeepSeek 官方价变动
    单价  ¥0.5 → ¥0.6 / 百万 tokens    （来源：OpenRouter · 今天 09:12）
    影响：路由排序会变—— Kimi 从 第 3 名 跳到 第 1 名
    [替换为新价]      [忽略 · 24h 不再提醒 ▾]        [×]
```
- 点 [忽略 · 24h ▾] 展开小选单：`[2 小时] [24 小时(默认)] [3 天] [7 天] [永久]`。
- [×] = 仅收起本条（临时关闭，不算"忽略设置"；24h 去重内不再主动弹出本条，但其它模型的漂移仍会弹）。

**文案 · 替换成功后（success toast，3s）：**
```
✅ 已用新价 ¥0.6/M
   路由已按新价重排：Kimi 第 3 → 第 1。需要改回，随时在「模型定价」里手动覆盖。
```

**文案 · 忽略后（info toast，3s）：**
```
ℹ️ 已记住：24 小时内不再提示 DeepSeek 的价格变化
   期间价格保持 ¥0.5/M 不变；到期（明天 09:12）会重新检测。
```

**文案 · 微调无跳名（低优先，drift>阈值但 orderChanged 为空 → 用 info toast 而非 banner）：**
```
ℹ️ DeepSeek 报价微调：¥0.5 → ¥0.52 /M，暂未改变路由顺序。   [知道了]
```

**文案 · 用户已手动覆盖过（_userSet:true）：** 不弹"替换"，仅提示一次后自动收起：
```
ℹ️ DeepSeek 官价变了（¥0.5→¥0.6），但你已手动锁定 ¥0.5——按你的设置保持不变。  [知道了]
```

每个按钮旁均满足 K1：先讲发生啥，再讲对路由/钱的影响，最后给"下一步"。

### 1.4 交互状态机（点击后发生什么）

```
IDLE（无漂移 / 已去重 / 已处理）
  │  refresh-pricing.cjs 产出漂移事件(>10% & 非 _userSet & 未被 suppress)
  ▼
DETECTED ──orderChanged 非空──▶ BANNER_SHOWN（顶部条幅，未处理不消失）
  │   orderChanged 为空
  └────────────────────────────▶ INFO_TOAST（"微调未跳名"，[知道了]）
                                   │ [知道了] / 3s
                                   ▼
                                 IDLE

BANNER_SHOWN
  ├─ [替换为新价] ──▶ write L1: {price, _userSet:true, source:'official-<渠道>', updatedAt}
  │        ──▶ 重排 rankByCost ──▶ BANNER_APPLIED ──(success toast,3s)──▶ IDLE
  │        （用户主权生效；此后该价受 _userSet 保护，再漂移只可忽略不可自动替换）
  │
  ├─ [忽略 · N天] ──▶ set PROXY_PRICE_DRIFT_SUPPRESS[DeepSeek] = N*24h
  │        ──▶ SUPPRESSED（该模型同类漂移 N 天内不再弹）──(info toast,3s)
  │        ──(N 天到期 / 手动改价 / 重新刷新)──▶ 回到 DETECTED 复检
  │
  ├─ [×] 收起 ──▶ DISMISSED（仅本条收起；24h 去重内不主动重弹，其它模型照常）──(可手动"查看告警")──▶ BANNER_SHOWN
  │
  └─ 期间再来一个模型的漂移 ──▶ 并列第二条 banner（每模型一条，互不覆盖，最多堆叠 3 条 + "另有 N 条"）
```

**关键不变量：** 任何分支都不自动改价。"替换"是唯一改价动作，且需显式点击；点击写入 L1 并标 `_userSet:true`，从此该价归用户主权。

### 1.5 边界与降级
| 场景 | 表现 | 铁律 |
|------|------|------|
| 刷新网络挂 | 不产新漂移 → 不弹；banner 区可显弱提示"价格数据已过期 X 小时（用最后一次刷新值）"，不阻塞 | K4 不假死 / 不阻塞 |
| `source` 拉不到 | 来源字段显"未知渠道，建议手动核对"（`--color-warning`），绝不显原始字段/JSON | K1 可读 |
| 同模型高频波动（OpenRouter 抖动） | 24h 去重压成一条；超过 3 条同类 → 合并为"DeepSeek 近 24h 价格波动 N 次，最新 ¥0.6，[查看] [忽略]" | 防刷屏 |
| 用户已 `_userSet` 锁定 | 不弹"替换"，只 info 提示一次（见 §1.3） | K2/K5 |
| suppress 期间价又变更大（如 >30%） | 仍受 24h/自设 N 天保护；但"永久忽略"模型在刷新页给一个"已忽略 N 天"角标可一键取消 | 用户可恢复 |

### 1.6 与架构稿对应
- **§3.10 价格变动覆盖 UX**：本表面 1:1 落实"允许覆盖但不强制 + 明显条幅/toast + 可替换/可忽略设时长（默认 24h）"。
- **§3.2 漂移哨兵**：`orderChanged` 载荷 = §3.2 关键字段；"绝不自动覆盖、用户主权 > 官价"。
- **§3.7 价表**：替换后写入 L1（`pricing-overrides.json`，`_userSet:true`），刷新写 L2（`pricing-cache.json`）不动 L1。
- **alert.js 契约**：`PROXY_PRICE_DRIFT_NOTIFY` 门控 + `cooldownMs` ≈ 24h 去重。

### 1.7 老板可能要调（D-A）
- **D-A1 · toast 默认是否可见**：建议"toast 只读镜像默认可见"（它是哨兵的整点意义，且零副作用），但**改价仍 100% 需用户点"替换"**。若老板想默认关，则仅在"价格中心"页给一个手动"查看待处理价格变动"入口。
- **D-A2 · 忽略时长档**：默认 24h，是否要"永久忽略"或更细（2h/6h）。
- **D-A3 · 微调阈值**：orderChanged 为空时是否也弹（现设计：用低优先 info toast，不堆 banner）。
- **D-A4 · 堆叠上限**：同类/跨模型 banner 最多堆几条（现建议 3 + "另有 N 条"）。

## 2 · 表面 B · 币种换算显示（§3.5 + §3.5.1 + §3.9）

### 2.1 设计意图
老板纠错：USD 必须能进路由（有 gpt 额度、复杂任务可能只有 gpt 能做）。价按**厂商原始币种**存（gpt=USD，kimi/glm=¥CNY），**换算成 CNY 参与路由比价**；但前端必须**原币 + 换算 CNY 并列**显示，让用户看清充值币种不被混淆（§3.5 末尾老板 Q5 明确交交互设计师）。

### 2.2 触发时机与门控
| 项 | 取值 | 说明 |
|----|------|------|
| 触面位置 | 路由结果列表 / 计费结果列表 / 模型定价页，每个模型一行 | 凡出现"单价/费用"处均按并列规范 |
| 门控 · 汇率源 | §3.5.1 推荐 **方案 C**（缓存 + 手动刷新，热路径零网络）；默认 `PROXY_FX_RATE=7.2` 兜底 | 开放项，老板定 A(env)/B(拉API)/C(缓存刷新) |
| 路由比价口径 | `costCNY = estimateCost(...) × fxRate[currency→CNY]`，CNY 汇率=1 | 路由排序按 CNY 比，原币仅展示 |
| 前端门控 | 无独立门控（纯展示）；但"汇率设置"入口受 `PROXY_FX_RATE`/`pricing-cache.json.fx` 驱动 | 显示不阻塞，缺值走降级 |

### 2.3 文案示例（统一格式：`原币 /百万tokens  ≈  ¥X.X/M`，原币主色、换算次要色、`≈` 衔接、数字用 `--font-mono`）

**USD 模型（路由场景，gpt 类）：**
```
gpt-5.4          $2.50 /百万tokens  ≈  ¥18.0/M
                 ↑ 原币(充值 USD)   └ 按汇率 7.2 换算，路由按此 ¥ 金额比价
```
小问号 `?` 悬停/点按 tooltip：`美元计价，按实时汇率 7.20（USD→CNY）换算为人民币；路由比价按人民币金额。你充的是美元，这里只是帮你统一比价，不会改你的币种。`

**CNY 模型：**
```
kimi-k2.6        ¥6.5 /百万tokens
deepseek-v4-pro  ¥0.5 /百万tokens   （官方价 · 今天 09:12）
```
CNY 模型不强行凑 `≈`，避免噪音；仅在"汇率异常"时给弱提示（见 §2.5）。

**本地免费模型：**
```
qwen3.8:27b-mlx  本地免费（¥0）
agnes-2.5-flash  免费（¥0）
```

**订阅模型（§3.4/§3.9 共享订阅配额，双维度分开算）：**
```
kimi-k2.7-code   ¥199/月（Allegretto · 含约 5,000 万 tokens·estimate）
                 边际 ≈ ¥0.004/M（用满额度时近乎免费）
```
tooltip：`这是包月订阅价，非按 token 计；同订阅下 kimi 系模型共享这一额度（§3.9）。token 数为估算，请按真实用量在设置里调整。`

**汇率来源徽标（每行末尾小字）：**
- 正常：`(fx 7.20 · 今天刷新)`
- 兜底：`(fx 1:1 · 汇率暂不可用，仅估算)` + 整行 `--color-warning` 描边

### 2.4 交互状态机
本表面以"展示 + 1 个设置入口"为主，状态机聚焦**汇率数据健康度**：

```
FX_OK（fx 来自 env/缓存，>0 且 ≤ 合理区间 6.5–8.0）
  │  显示 "≈ ¥X/M (fx 7.20 · 今天刷新)"，USD 行原币+CNY 并列
  ▼
正常展示

FX_FALLBACK（拉不到 / =0 / 非正 / 过期 > TTL 7d）──▶ 退化 fx=1.0, fxSource='fallback'
  │  USD 行显示 "≈ ¥2.50/M (fx 1:1 · 汇率暂不可用，仅估算)" + warning 描边
  │  （路由此时 USD 模型显得"极贵"被降权——属已知副作用，必须显性可见）
  ▼
展示 + 顶部弱提示条： "汇率暂不可用，已按 1:1 估算，比价可能失真；可点[设置]手填 PROXY_FX_RATE 或[刷新汇率]"

刷新动作（用户点[刷新汇率] 或 refresh-pricing.cjs 一并刷）
  ├─ 成功 ──▶ FX_OK（缓存 pricing-cache.json.fx + updatedAt + source）
  └─ 失败 ──▶ 停留 FX_FALLBACK + info toast "汇率刷新失败，仍用上次值(或 1:1)"，不阻塞
```

### 2.5 边界与降级
| 场景 | 表现 | 铁律 |
|------|------|------|
| 汇率拉不到 / 0 / 非正 | 退化 `fx=1.0`，`fxSource='fallback'`；显示"≈ ¥X/M (1:1·仅估算)" + warning；**绝不静默混算、绝不产假 CNY** | K3 原币不丢 / §3.5 不产假 |
| USD 模型被降权（fx=1 时显极贵） | 路由排序会把它排后；列表顶部给一行弱提示"汇率 1:1 下外币模型比价偏高，建议设汇率"，避免老板误以为"这些模型太贵不能用" | K1 可读，告知"为什么排后" |
| 原币为罕见币种 | 原币符号如实显示 + 换算 CNY + tooltip 标注"该币暂按估算汇率" | K3 |
| 订阅 token 数未知 | 显"含约 N 万 tokens · estimate" 并 tooltip"用户可改"，绝不把 estimate 当官方 | §3.6/§3.9 诚实边界 |
| 数值精度 | 原币与换算各显 2–3 位有效数字，按币种惯例（USD 2 位、CNY 2 位）；避免长串小数 | 可读 |

### 2.6 与架构稿对应
- **§3.5 currency**：原币保留 + 换算 CNY 参与路由；前端"原币 + 换算并列"是 §3.5 末尾数据契约的 UI 落地。
- **§3.5.1 汇率源**：A/B/C 方案 + 默认 fx 兜底（建议 7.2）——本表面把"兜底=1.0 + 显性标注"的降级可视化。
- **§3.9 共享订阅配额**：订阅行按 subscription 粒度显示"含约 N tokens·estimate"，与配额预检（表面 C）共用同一数据。
- **§3.4 双维度**：API 按 token / 订阅按包月分成两组行，边际成本分算。

### 2.7 老板可能要调（D-B）
- **D-B1 · 汇率源 A/B/C**：§3.5.1 推荐 C，请老板拍。
- **D-B2 · 兜底值**：默认 7.2 是否作硬兜底，还是拉不到时直接 1:1 标注（现设计：1:1 + 显性 warning 最安全，7.2 仅用于"缓存里最近一次"）。
- **D-B3 · 并列排版**：原币前 / 换算后（默认）；是否允许在设置里切"只显示 CNY / 只显示原币 / 并列"。
- **D-B4 · USD 降权提示**：fx=1 时是否自动在路由结果页顶部加"比价失真"条（建议加）。

## 3 · 表面 C · 配额耗尽预警（§3.8 + §3.9）

### 3.1 设计意图
项目差异化招牌能力（老板原话）。类比 **hermes agent 上下文压缩**：压缩 = 上下文用尽前 checkpoint；本能力 = **配额用尽前 checkpoint**。两件套：① 执行前预检"够不够本任务"；② 执行中接近 80% 先存进展+优雅停。**绝不假死**。门控 `PROXY_QUOTA_GUARD` observe 默认关。

### 3.2 触发时机与门控
| 项 | 取值 | 说明 |
|----|------|------|
| 门控 | `PROXY_QUOTA_GUARD`（observe，默认**关**） | 关 = 三选一仅"建议"不强制拦；开 = 预检可硬拦 + 80% 可硬停 |
| C1 预检 | 任务启动前，热路径内**零网络**算：本任务预估 token N vs 当前订阅 X 剩余 Y | 够→直接执行；不够→三选一（继续/降档/暂停） |
| C2 监测 | 执行中持续监测配额消耗，**接近用尽（默认 80%）** 时先 checkpoint + 提示 + 优雅停 | 阈值可配 `PROXY_QUOTA_WARN_PCT`（默认 80%） |
| 诚实边界 | 配额/token 精确值依赖各家 API（部分无精确接口） | 预估可能偏差；偏差时**宁可早停**；预检失败**不阻塞**，带 warning 执行 |
| 粒度 | 按 **subscription** 粒度（§3.9 共享 credit 池），非 per-model | kimi 199 订阅下 kimi 系共享同一 Y |

### 3.3 文案示例

**C1 · 执行前预检——够（静默，可选 success toast 1.5s）：**
```
✅ 配额充足：本任务约需 12 万 tokens，当前 kimi 订阅剩 42.3M，够本次。开始执行。
```

**C1 · 不够——三选一弹窗（`role="dialog"`，焦点进、Esc 关、焦点陷阱）：**
```
⚠️ 配额可能不够本任务
    本任务预估：约 18 万 tokens
    当前 kimi 订阅（Allegretto ¥199/月）剩余：约 0.9M（≈ 1%）
    直接继续大概率在中途触发降级或停下。

    [继续 明知可能超额]   [降档→ 切 deepseek（更省，本次约 ¥0.03）]   [暂停任务]

    继续：用当前模型硬跑，可能中途卡住（已开"中途先存进展"保护）
    降档：换更省模型，本次成本低、配额够；任务目标不变
    暂停：先不做，等充值/换订阅/降档后再跑
```
（每个选项下方一句话讲"下一步"，满足 K1。）

**C2 · 执行中到 80%——暂停型 banner（自动 + 先存）：**
```
⏸️ 已用掉约 80% 配额——已自动保存进展
     当前任务进展已存到 checkpoint-0922-1405（可随时恢复，不会丢）。
     为避免中途丢失，任务已优雅暂停（不是卡死，是"先停下保结果"）。

     [继续（可能超额）]   [查看已保存的进展]   [换更省模型继续]
```
（类比 hermes 上下文压缩的文案口吻：「先 checkpoint 再压缩」→「先存进展再优雅停」。）

**C1 · 预检失败/配额拿不到——不阻塞（info 带 warning 角标）：**
```
⚠️ 配额数据暂不可用，无法预判是否够用
    已按经验继续执行；若中途接近上限，会自动先存进展再停（已开执行中保护）。
    [知道了]   [仍要预估（手动输入剩余 token）]
```

### 3.4 交互状态机

**C1 执行前：**
```
TASK_START
  │ 预检：N(本任务预估) vs Y(订阅剩余)，热路径零网络
  ├─ Y 够 ──────────────▶ EXECUTING（可选 success 提示）
  ├─ Y 不够 ──▶ CHOICE_MODAL（三选一，焦点陷阱）
  │      ├─ [继续]    ──▶ EXECUTING（带"可能超额"标记 + 强制开 C2 保护）
  │      ├─ [降档 X]  ──▶ re-route 到更省模型 X ──▶ 重算预检 ──(够)──▶ EXECUTING
  │      │                                    └─(仍不够)──▶ 回 CHOICE_MODAL（候选更省列表）
  │      └─ [暂停]    ──▶ PAUSED（任务入"待恢复"队列，可一键恢复）
  └─ Y 拿不到 ──▶ EXECUTE_WITH_WARNING（不阻塞，带 warning 角标 + 自动开 C2 网）
```

**C2 执行中：**
```
EXECUTING ──(消耗 < 80%)──▶ EXECUTING
  ──(消耗 ≥ 80% · PROXY_QUOTA_WARN_PCT 默认 80%)──▶
CHECKPOINTING（先存进展，写 checkpoint-<时间戳>）
  ──▶ PAUSED_GRACEFUL（优雅停，banner 三选一）
       ├─ [继续]           ──▶ RESUME（可能超额，继续监测）
       ├─ [查看已保存]    ──▶ 打开 checkpoint 视图（read-only 展示进展）
       ├─ [换更省模型]    ──▶ re-route（同 C1 降档）──▶ RECHECK → 够则 RESUME
       └─ 用户/超时 ──────▶ 保持 PAUSED_GRACEFUL（不假死，进展已存，随时恢复）
```
**关键不变量（K4）：** 任何"不够/拿不到"分支都先存进展、都给出"下一步"、都不卡死。宁可早停（误判不够而停）胜于假死。

### 3.5 边界与降级
| 场景 | 表现 | 铁律 |
|------|------|------|
| 配额/余额拿不到（API 无精确接口） | **不阻塞**，带 warning 执行 + 自动开 C2 网（§3.8 诚实边界） | K4 不假死 / "宁可早停" |
| 预估偏差大 | 阈值偏保守（80% 可下调到 60–70%），**宁早停** | K4 |
| 订阅剩余额度未知（estimate） | 显"剩余约 N·estimate"，预检标低置信，倾向 [降档]/[暂停] 而非 [继续] | §3.6/§3.9 不产假 |
| 降档候选为空（无更省模型） | [降档] 置灰 + 提示"无更省候选，请充值或暂停" | 不静默 |
| 门控 observe（默认关） | 三选一/暂停均为**建议**，不强制拦；老板翻执行态后才硬拦/硬停 | K5 默认关 |
| 多订阅共享（§3.9） | 预检/监测按 subscription 聚合 Y，kimi 系共享，避免各算各得 | §3.9 |

### 3.6 与架构稿对应
- **§3.8 配额耗尽优雅降级**：本表面 1:1 落实"执行前预检 + 执行中 80% checkpoint+优雅停 + 类比 hermes 上下文压缩 + 绝不假死 + 门控 observe"。
- **§3.9 共享订阅配额**：Y 按 subscription 粒度（共享 credit 池），estimate 诚实标注。
- **§3.4/§3.6**：订阅维度 `monthlyCny / monthlyQuotaTokens` 边际成本 + token 数 estimate 处理。
- **门控**：`PROXY_QUOTA_GUARD`(observe 默认关) + `PROXY_QUOTA_WARN_PCT`(80%)。

### 3.7 老板可能要调（D-C）
- **D-C1 · observe vs 执行**：默认 observe（建议，不强制）；翻执行态属老板单点决策——本稿给两档文案差异（"建议" vs "已拦/已停"）。
- **D-C2 · 80% 阈值**：默认 80%，是否按"宁早停"下调到 60–70%。
- **D-C3 · "继续（可能超额）"默认**：高风险操作是否需二次确认（建议需，防误点）。
- **D-C4 · 降档目标选谁**：默认按 costCNY 取"够配额的次省模型"；要不要让用户在弹窗里手动挑。
- **D-C5 · checkpoint 存放/保留**：checkpoint 命名/保留几份/是否可回滚（本稿只定交互，落库交后端）。
