# Proxy Rebuild 管理面板 字段级体验评审报告

**评审对象**：http://localhost:18792（Docker 运行，4 容器均 Up）｜**方式**：只读探测 + 源码比对，未修改任何文件

## 🔴 P0：首次使用流程被完全阻断（最严重）

新用户打开面板 → 点击「去设置密码」→ 填写符合强度的密码 → 提交必然失败：

- **证据**：`POST /api/auth/login` 返回 `{"success":false,"error":"Failed to save password, check file permissions"}`；容器日志反复出现 `[Auth] Failed to write password file: EISDIR ... open '/root/.multi-proxy-password'`
- **根因**：docker-compose 将卷挂载到 `/root/.multi-proxy-password`，Docker 自动创建了**目录**；而 `server.js:75` 把它当**文件**写（`fs.writeFileSync(PASSWORD_FILE, hash)`），EISDIR 必然抛错
- **体验雪崩**：密码设不了 → 所有需认证 API（启停、日志、供应商 CRUD、余额）全部 401 → 整个面板除静态卡片外不可用。错误文案还误导用户去查「文件权限」，实际是部署缺陷，普通用户永远猜不到

## ✅ 做得好的地方

1. **登录页双模式自动检测**：前端调 `/api/auth/status` 的 `needsSetup` 自动切换「设置管理员密码」/「欢迎回来」界面，无需用户理解概念（login.html:1093）
2. **表单即时校验 + 密码强度条**：「密码长度至少为 8 个字符」「两次输入的密码不一致」中文提示清晰；4 格强度条可视化（login.html:981/986）
3. **反馈覆盖较全**：全局 loading bar、toast 成功提示（「已导出 N 条日志 (TXT)」）、按钮 loading 态（「测试中...」）、限流倒计时提示「尝试次数过多，请 X 分钟 后再试」均有
4. **忘记密码有自救引导**：弹窗分步骤给出命令并支持一键复制（login.html:753-763）
5. **安全头齐全**：CSP/X-Frame-Options/nosniff/Referrer-Policy 都在，登录有速率限制
6. **降级提示**：后端不可达时显示横幅「后端服务未运行…」而非白屏
